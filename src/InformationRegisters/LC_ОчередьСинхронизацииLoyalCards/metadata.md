# Регістр відомостей: LC_ОчередьСинхронизацииLoyalCards

**Синонім:** Черга синхронізації Loyal Cards  
**Призначення:** облік контрагентів, для яких потрібно передати оновлений `balance` в API після рухів по регістрах BAS.

## Властивості

| Властивість | Значення |
|-------------|----------|
| Періодичність | Неперіодичний |
| Режим запису | Незалежний |
| Підчинення регістратору | Ні |

## Структура

### Виміри

| Ім'я | Тип | Ведучий |
|------|-----|---------|
| `Контрагент` | `СправочникСсылка.Контрагенты` | Так |

### Ресурси

| Ім'я | Тип | Опис |
|------|-----|------|
| `ДатаИзменения` | `Дата` | Коли баланс змінився в BAS |
| `ДоступныйБаланс` | `Число(15,2)` | Значення для передачі в API |
| `Синхронизировано` | `Булево` | Чи передано в API |
| `ДатаСинхронизации` | `Дата` | Коли успішно синхронізовано |
| `ТекстОшибки` | `Рядок(500)` | Остання помилка API |

## Модуль менеджера

`ManagerModule.bsl` — `ДобавитьВОчередь()`, `ПолучитьНесинхронизированные()`, `ОтметитьСинхронизированным()`, `ЗафиксироватьОшибку()`.

## Використовується в

- `LC_СинхронизацияLoyalCards` — після проведення чеків і регламенту
- Регламент `LC_АктивацияИСгораниеБонусов` — обробка несинхронізованих записів
